\section{AutoPatch}
The AutoPatch dataset contains high-severity CVEs disclosed in 2024 and 2025 and collected from the GitHub Advisory Database, Openwall, and the Chromium issue tracker with a custom crawler.
For each CVE, the entry pairs were augmented using 5 LLMs:  Code Llama (13b-instruct), DeepSeek Coder (v2-lite), DeepSeek-R1 (32b), GPT-4o, and OpenAI o3-mini.
The augmentation strategies used were: "inserting unreachable code fragments, adding random code in comments, varying whitespace and formatting, defining a useless function, and introducing extraneous newline characters".

\section{CVEfixes}

CVEfixes\cite{moonen2024cvefixes} is a vulnerability dataset for data-driven security research automatically collected and curated from Common Vulnerabilities and Exposures (CVE) records from the public U.S. National Vulnerability Database (NVD). 
The dataset includes detailed information about the Pull Request CVE resolution, such as the commit-, file-, and method level, as well as the repository- and CVE level.
The general statistics are shown below: 

\begin{itemize}
    \item\textbf{CVEs} 11,873 vulnerabilities
    \item\textbf{commits}] 12,107 fix commits
    \item\textbf{files} 51,342 changed files
    \item\textbf{methods} 277,948 method changes
    \item\textbf{CWE types} 272 distinct types
    \item\textbf{projects} 4,249 open-source projects
\end{itemize}

% Origin, Collection method, Composition used
This project uses version v1.0.8, which covers all published CVEs up to 23 July 2024. According to the authors, the projects considered in this dataset include all open-source projects that were reported in CVE records in the NVD in this time frame and had publicly available git repositories. The dataset is stored in a relational database, containing 272 different CWE types across 12107 vulnerability-fixing commits from 4249 open-source projects. The dataset includes the source code before and after changing 51342 files and 138974 functions.

\subsection{Fix Description Encoding}
 
The AutoPatch is structured into folders where each entry is stored in a folder containing a description JSON (\texttt{db\_entry.json} file=, which includes a field describing the remediation strategy at a symbolic, variable-agnostic level (\texttt{fix\_list}).
The fix description is using symbolic names with variable and function
mappings (e.g., \textit{''add a NULL check before dereferencing the
pointer''}) lets a fixed pattern learned from one example
be transferred to a structurally similar target function. 
With this description, the LLM is expected to use the abstract fix description to apply the required changes to the target using the actual identifiers. 
Section~\ref{chapter:methodology} details how this field is used when constructing prompts for patch generation.

The extracted corpus is predominantly C code (92\%), consistent with the kernel- and
system-level focus of the pipeline; on average, a patch adds 22 lines and
removes 5 lines, reflecting the generally asymmetric nature of security
fixes.

As a dataset collected from real-world cases with low preprocessing, it will be used to verify the methodology in real-life settings, especially when compared against the 75-sample AutoPatch corpus highly curated by the team.

\subsection{Complexity Description}
\paragraph{CWE-787: Out-of-Bounds Write :} occurs when a program writes data past the end, or before the beginning, of an intended memory buffer. This flaw can lead to memory corruption, process crashes, or the execution of arbitrary code. The testing sample consists of C++ implementation files from the TensorFlow and TensorFlow Lite runtime/kernel libraries, focusing on kernel operations, tensor management, custom audio operators, and model-building infrastructure.

\paragraph{CWE-362: Concurrent Execution using Shared Resource with Improper Synchronization / Race Condition :}Occurs when a program performs two or more operations concurrently, and the outcome depends on the non-deterministic sequence of execution. If shared resources (memory spaces, sockets, files) are accessed without proper synchronization primitives, concurrent threads can manipulate memory unexpectedly, leading to privilege escalation, data corruption, or crashes.

The CWE-362 sample consists of 15 instances across 6 unique CVEs, originating predominantly from lower-level C code within the Linux Kernel (network stack \texttt{net/ipv4}, storage systems fs/ext4) and cryptographic/communication libraries (e.g., OpenSSL/SRTP).

Rather than relying on naive global locks, the ground-truth patches exhibit high domain-specific synchronization complexity:

CVE-2012-3552 consists of Domain-Specific Socket Locking and represents 53\% of the class sample. Fixes rely on socket-specific concurrency macros (\texttt{lock\_sock}/\texttt{release\_sock}) and kernel-level Read-Copy Update (\texttt{rcu\_dereference}, \texttt{rcu\_assign\_pointer}) primitives to safely manage \texttt{ip\_options} memory across concurrent socket writes.
File System Read-Write Inconsistencies \& Semaphores (CVE-2012-4508, CVE-2015-8839) involve ext4 race conditions between page faults and file truncation (\texttt{fallocate}/\texttt{truncate}), requiring reader-writer semaphores (\texttt{i\_mmap\_sem}) or explicit inconsistency flags instead of adding simple mutexes.
Structural Decoupling \& Flagging (CVE-2020-12652, CVE-2021-32686) is solved either by passing objects directly to eliminate state copies or by enforcing strict synchronization across concurrent SSL resource access paths without basic \texttt{lock}/\texttt{unlock} wrappers.


\paragraph{CWE-20: Improper Input Validation :}
Occurs when an application fails to validate, sanitize, or verify input before processing it, based on the expected structural, length, or character format requirements.
The sample is composed of 15 evaluations of a single vulnerability (CVE-2021-26788) in C/C++. The fix pattern consists of inserting input-character bounds checks (e.g., validating hex strings via \texttt{isxdigit()}) to ensure that user-supplied input strings conform to expected formats before execution.

\paragraph{CWE-190: Integer Overflow or Wraparound :}
Occurs when an arithmetic calculation produces an integer value outside the representable range of the specified data type, typically resulting in undersized buffer allocations.
The sample consists of 15 instances of CVE-2023-36326 evaluated in different pipeline configurations. The fix pattern requires inserting safe integer-arithmetic checks before dynamic memory operations (\texttt{malloc}, \texttt{realloc}) to prevent small, wrapped-integer sizes from being allocated for large data streams.

\paragraph{CWE-416: Use After Free (UAF) :}
Occurs when an application continues to use a memory pointer after it has been explicitly deallocated or freed. This can lead to arbitrary code execution, heap corruption, or diversion of execution paths.
The sample contains multiple CVEs of C/C++ network stack and media-streaming components, including CVE-2016-3841 (Linux IPv6 socket lifecycle), CVE-2023-38703 (SRTP session cleanup), CVE-2023-3863, CVE-2019-11487, and CVE-2022-0156. The patch consists of resetting dangling pointers to \texttt{nullptr}, managing reference counts, or ensuring that asynchronous destructor routines do not access freed memory blocks.

\paragraph{CWE-476: NULL Pointer Dereference :}
Occurs when a program attempts to read or write memory using a pointer variable that evaluates to \texttt{nullptr}, leading to Denial of Service of the application.
The sample is a multi-CVE split, which includes media processing frameworks and proxy servers, such as CVE-2019-19815 (GPAC multimedia handling), CVE-2020-10739 (Istio/Envoy proxy handling), CVE-2023-24832, and CVE-2018-20786. The patches consist of applying explicit null-check guards (\texttt{if (ptr == nullptr) return;}) or safe-access wrappers before accessing the fields.
